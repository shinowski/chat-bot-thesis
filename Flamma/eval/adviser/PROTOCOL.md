# Adviser evaluation protocol — 22 October 2026

1. Author and freeze 260 new fictional English messages (20 per intent). Record a SHA-256 checksum before any prediction. Reject normalized exact overlap with training sources and previous test JSON/Python strings. Record template-group overlap separately; do not imply semantic independence from exact deduplication. Labels are author-assigned and require independent human review.
2. Keep this new final set out of training, regularization selection, confidence-threshold tuning, error-driven fixes, and activation decisions. Use the old, repeatedly used 130-message benchmark and newly authored development examples for development. Preserve v5 unchanged.
3. Fix the known seven development errors in a separately versioned candidate. Select regularization on grouped development validation. Record all attempts. Lock the candidate artifact and all application source hashes before the new final evaluation. Do not change the candidate after inspecting final results; report failures. Any later change needs another untouched test set.
4. Evaluate both original v5 and the locked candidate on the new final set once; report accuracy, macro precision/recall/F1, per-intent metrics, confusion matrices, predictions, and overlap audit. This is a newly authored local engineering test, not independently collected clinical evidence.
5. Run existing and additional safety, integration, conversation, persistence, retry, and browser checks. Label simulated image responses explicitly. Measure local text latency and actual model processing separately from synthetic image fixtures. Do not claim human usability from browser automation.
6. Evaluate active image v10-1 only against a supplied held-out image manifest, with documented split provenance. Report raw classifier metrics on all labeled supported images, gate coverage, accepted-only metrics, rejection rates per class, unsupported rejection, and latency. Do not silently remove rejected images from denominators. Do not calibrate gates on the final image set.
7. A dermatologist must review and sign recommendations, red flags, referral rules, unsupported-condition behavior, and failure cases. Prepare review material; retain awaiting-validation status until an actual review occurs. Do not send material to others without the user's instruction.
8. Publish a status checklist distinguishing completed software checks, observed failures, and work requiring image data, a dermatologist, or human participants. Never fabricate missing metrics or approvals.
